# GrowthScout AI — Evaluation Contract

This contract serves as the authoritative architectural specification and quality standard governing all evaluations, datasets, baselines, and CI/CD gates within the GrowthScout AI repository.

---

## 1. Datasets Contract

The framework maintains five mandatory golden datasets for core agent tasks, plus specialized operational verification datasets:

1.  **Discovery Dataset (`discovery_dataset.json`)**:
    *   *Target*: Discovery Agent.
    *   *Coverage*: Coordinate parsing, local niche queries, lead constraints, and local markets.
    *   *Cases count*: 30 cases.
2.  **Website Analysis Dataset (`analysis_dataset.json`)**:
    *   *Target*: Web Analyzer Agent.
    *   *Coverage*: Site timeouts, Robots.txt blocks, CMS detections, scraping limits.
    *   *Cases count*: 30 cases.
3.  **Recommendation Dataset (`recommendation_dataset.json`)**:
    *   *Target*: Growth Agent.
    *   *Coverage*: Recommendations actionability, domain compliance, campaign blueprints.
    *   *Cases count*: 30 cases.
4.  **Competitor Dataset (`competitor_dataset.json`)**:
    *   *Target*: Competitor Analysis.
    *   *Coverage*: Niche competitor benchmarking, reviews count, rating averages.
    *   *Cases count*: 30 cases.
5.  **Opportunity Scoring Dataset (`opportunity_scoring_dataset.json`)**:
    *   *Target*: Opportunity Agent.
    *   *Coverage*: Opportunity categorizations, confidence degradation penalties, scoring logic.
    *   *Cases count*: 30 cases.

### Dataset Fingerprints
Every dataset JSON structure must validate against standard JSON draft-07 schemas. Dataset integrity is audited using three independent SHA-256 hashes generated by `dataset_integrity.py`:
*   `schema_hash`: Audits JSON schema structure or schema declarations.
*   `content_hash`: Audits the array of cases (excluding metadata headers).
*   `metadata_hash`: Audits the metadata block.

## 2. Metrics Contract

All agent evaluation results are graded against the following metrics pool configured in `eval_config.yaml`:

### Deterministic Metrics (Hard Gates)
These metrics evaluate logical correctness and code contracts. They require a score of `1.0` (100% pass):
*   `schema_validation`: Ensures output matches drafts-07 schema contracts.
*   `routing_correctness`: Verifies that the workflow orchestrator traverses the correct topology paths.
*   `tool_usage`: Checks that MCP server functions are executed with valid parameters.
*   `state_transitions`: Validates execution state transitions.
*   `lead_score_correctness`: Validates that Opportunity scores match valuation heuristics exactly.

### Probabilistic Metrics (Soft Gates)
These metrics evaluate quality and semantic depth using LLM-as-a-judge rubrics. Score range is `0.0 to 1.0`:
*   `business_recommendation_value`: Target threshold `>= 0.85` (Consulting depth, relevance, actionability).
*   `report_readability`: Target threshold `>= 0.80` (Markdown organization, flow, consultative tone).
*   `consultant_confidence_score`: Target threshold `>= 0.80` ( линейно normalized from a 1-5 rubric rating evaluating client readiness without manual edits).

## 3. Baselines & Gate Behavior

*   **Versioned Baselines**: Dynamic/moving regression baselines are prohibited. Evaluations must compare against versioned baseline files stored under `eval/baselines/` (e.g., `sprint_6.2_baseline.json`).
*   **Gate Enforcements**:
    *   **Fast CI Pipeline (PRs)**: Enforces deterministic metrics (fails on violation) but logs warnings for probabilistic failures without blocking build. Uses dataset subsets (5 cases per dataset).
    *   **Full Evaluation Pipeline (Nightly/Release)**: Enforces both deterministic and probabilistic gates. Blocks release on any failure unless the `BYPASS_PROBABILISTIC_GATES=true` env bypass is present. Uses complete datasets (30 cases per dataset).

---

## 4. Reproducibility & Continuous Improvement

*   **Reproducibility Tracking**: The trend engine calculates standard deviations to log `evaluation_variance`, `judge_consistency`, and `reproducibility_rate` to quality history log.
*   **Prompt Optimization Safety Invariant**: Prompt optimization processes must NEVER modify production prompt files automatically. The optimizer runs candidates through A/B evaluation, logging results to the candidate dashboard, requiring manual Git commit and PR review to apply.

---

## 5. Backward Compatibility Guarantee

The preflight validation script (`validate_manifest.py`) asserts that older manifests, dataset files, and baseline log structures remain fully readable and parseable without runtime or execution failures.
