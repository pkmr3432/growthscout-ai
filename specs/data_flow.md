# Data Flow Specification: GrowthScout AI

This document maps the flow of data across the systems architecture during a typical business discovery, digital presence audit, and campaign proposal execution lifecycle.

---

## 1. Sequence Diagram: Core Execution Cycle

```mermaid
sequenceDiagram
    autonumber
    actor User as Consultant (Next.js UI)
    participant Gateway as FastAPI Gateway
    participant Orch as ADK Orchestrator
    participant Discovery as Discovery Agent
    participant Analyzer as Website Analysis Agent
    participant Opp as Opportunity Agent
    participant Prop as Growth Intelligence Agent
    participant DB as Firestore DB

    User->>Gateway: POST /api/v1/sessions {niche, location}
    Gateway->>DB: Initialize Session State (status = "idle")
    Gateway->>Orch: Start Orchestration Loop
    activate Orch
    Orch->>DB: Update Session Status (status = "discovering")

    Orch->>Discovery: Invoke Agent (Find leads)
    activate Discovery
    Note over Discovery: Queries Local Maps MCP
    Discovery-->>Orch: Return List of Leads (JSON)
    deactivate Discovery

    Orch->>DB: Update Session Status (status = "route_auditing_or_analysis")
    Note over Orch: Partition leads into website and no-website groups

    Orch->>DB: Update Session Status (status = "auditing")
    loop For each lead website
        Orch->>Analyzer: Invoke Agent (Audit URL)
        activate Analyzer
        Note over Analyzer: Queries Scraper MCP & SEO MCP
        Analyzer-->>Orch: Return Audit Findings (JSON)
        deactivate Analyzer
    end

    Orch->>DB: Update Session Status (status = "opportunity_analysis")
    Orch->>Opp: Invoke Agent (Identify gaps)
    activate Opp
    Opp-->>Orch: Return Gap Matrix (JSON)
    deactivate Opp

    Orch->>DB: Update Session Status (status = "report_generation")
    Orch->>Prop: Invoke Agent (Generate report)
    activate Prop
    Prop-->>Orch: Return Growth Intelligence Report (Markdown)
    deactivate Prop

    Orch->>DB: Save report drafts, update status = "awaiting_approval"
    Orch-->>Gateway: Return Execution Log Status
    deactivate Orch
    Gateway-->>User: Pushes Status Update (Websocket/HTTPS)
    Note over User: Consultant reviews report and clicks Approve

    User->>Gateway: POST /api/v1/sessions/{id}/approve
    Gateway->>DB: Read Session, apply updates
    Gateway->>DB: Update Status = "completed"
    Gateway-->>User: Return success response
```

## 2. Shared Context Payload Structures

### Step 5: Discovery Output Format
The payload passed from the `Business Discovery Agent` back to the orchestrator:
```json
{
  "leads": [
    {
      "business_name": "Austin Boiler Experts",
      "address": "401 W 15th St, Austin, TX 78701",
      "website_url": "https://austinboilerexperts.com",
      "google_rating": 4.6,
      "review_count": 82
    }
  ]
}
```

### Step 9: Website Analysis Output Format
The payload passed from the `Website Analysis Agent` back to the orchestrator:
```json
{
  "website_url": "https://austinboilerexperts.com",
  "audit": {
    "cms": "WordPress 6.4",
    "load_time_seconds": 6.8,
    "has_analytics": false,
    "has_facebook_pixel": false,
    "has_booking_widget": false,
    "has_schema_markup": false,
    "seo": {
      "title": "Boiler Repair - Austin",
      "description": "Boiler repairs and heating services in Austin Texas.",
      "h1_elements": ["Boiler Services"]
    }
  }
}
```

### Step 13: Growth Report Output Format
The final outreach message payload generated by the `Growth Intelligence Agent`:
```json
{
  "lead_name": "Austin Boiler Experts",
  "outreach": {
    "channel": "email",
    "subject": "Quick recommendation for Austin Boiler Experts",
    "body_markdown": "Hi Team,\n\nI visited your site at https://austinboilerexperts.com and noticed that page loads take over 6 seconds on mobile devices. According to search statistics, this may be causing a bounce rate of over 50% for your local heating search traffic...\n\nWould you be open to a 10-minute audit call this week?\n\nBest,\n[Consultant]"
  }
}
```
